## 1. 登録フローの画面遷移と各画面の役割

操作数を「**①写真を選ぶ → ②プロンプトをコピー → ③結果を取り込む → ④確認して保存**」の最小ステップに保ちつつ、手入力のみ・既存銘柄からの流用・複数本一括登録・登録後の編集を単一のモーダル（BottleFormModal の拡張）内でシームレスに行える構成とする。

### 画面遷移
1. **起動**：下部ナビゲーションの「登録」タップ、または詳細画面の「編集」タップでモーダルを開く。
2. **新規登録の3つの経路**：
   - **経路A（標準：写真＋Gemini相談）**：写真を複数枚選択（即座に端末内でリサイズ・EXIF除去）→ プロンプトをコピー → Gemini結果JSONを貼り付けて取り込み → 内容確認・修正して保存。
   - **経路B（2本目以降：既存銘柄から流用）**：上部の「既存銘柄から流用」ボタンから過去のボトルを選択 → 属性・解説・写真（任意）を引き継いで確認 → 購入情報や本数を指定して保存。
   - **経路C（手入力）**：Gemini相談を使わず、最初から手動で各項目を入力して保存。
3. **既存ボトルの編集**：
   - 登録済みボトルの全属性・解説・出典・購入情報・相場目安を編集可能。
   - 写真の追加・差し替え・削除・代表写真の変更が可能。
   - Gemini JSON の再取り込みが可能（ユーザーが手動編集した項目は上書きせず保護）。

### 各セクション・要素の役割
- **ヘッダー＆流用ボタン**：新規登録時は上部に「既存銘柄から流用して登録」ボタンを配置。
- **写真セクション**：複数枚写真（表・裏・箱など、上限10枚/本）の選択・追加。Canvas によるリサイズ・JPEG圧縮・EXIF除去。サムネイル一覧で代表写真指定（未指定なら1枚目）、差し替え、削除。
- **Gemini相談＆取り込みパネル**：
  - **背景写り込みへの注意表示**：「※Geminiに写真を添付する際は、部屋の様子や個人情報・反射の写り込みにご注意ください」をコピーボタン直上に常時明示。
  - **プロンプトをコピー**：選択中の種類ヒントや相談実行日を含めたプロンプトをクリップボードにコピー。
  - **結果JSONの取り込み**：ペースト用テキストエリアおよびワンタップ取り込み。
- **重複警告バナー**：JSON取り込み時または名前入力時に、既存の有効ボトルに同一銘柄キー（または正規化名＋種類が一致）が存在する場合、「同じ銘柄『〇〇』が既に登録されています（家にある酒 X本 / 飲んだ記録 Y本）」と警告し、流用への切り替えや別個体としての登録を案内。
- **既存銘柄流用ピッカー**：過去の全有効ボトルから銘柄を検索・選択し、基本属性・種類別属性・4部構成解説・出典・相場目安、および任意で写真を引き継ぐ。状態は「未開封」、購入情報はリセット。
- **確認・修正フォーム**：
  - 名前（必須）、種類（必須・10種）、状態（既定は unopened。opened/finished/disposed も可、開封日は空欄可）、容量（ml）、度数（%）、種類別属性。
  - 解説（4部構成：①ひとことで ②味わい ③背景 ④飲み方）と出典 URL（タイトル・URL）。
  - 購入情報（購入日・購入場所・購入価格）と相場目安（推定価格・取得日・補足）の完全分離。
  - 登録本数セレクタ（新規登録時のみ：1〜10本）。

## 2. Gemini 相談プロンプトの設計方針と、取り込み JSON のスキーマ

### (1) プロンプトの設計方針
- **役割と出力形式**：添付されたラベル・箱の写真（複数枚）を読み取り、Web 検索で裏付けを取った上で、指定の JSON 形式（コードブロック1つのみ）で出力させる。
- **正確さの原則（ハルシネーション抑止）**：
  - ラベルの文字と、信頼できるネット情報（公式サイト・蔵元／蒸留所・正規代理店・酒販店）で裏が取れた事実のみを記述する。
  - 裏が取れない属性値は null または空文字とし、解説文の中で不明な事項は推測で埋めず「不明」と明記する。
  - 解説の文字数は4部合計で 300〜500字を目安とするが、不明な点が多い場合は正確さを優先して短くなってよい。
  - 文体は事実ベースで淡々と記述し、宣伝文句や誇張表現を禁止する。
- **種類の固定制約**：category は必ず固定10種（日本酒 / ワイン / ウイスキー / ジン / 焼酎 / ビール / ブランデー / シェリー / ウォッカ / その他）のいずれか1つにする。

### (2) 種類別の解説の軸（全10種確定仕様）
- **日本酒**：
  - ②味わい：香り（吟醸香・穏やかさ）、甘辛・酸味・旨味のバランス、口当たりとキレ
  - ③背景：蔵元の所在地・歴史、使用米・精米歩合・仕込みの特徴
  - ④飲み方：おすすめの温度帯（雪冷え〜熱燗）、合う料理の系統
- **ワイン**：
  - ②味わい：果実味、酸味、タンニン（渋み）・ボディ（重さ）または泡の質感、余韻
  - ③背景：生産者（ドメーヌ／ワイナリー）、産地（AOC/GI等）と畑・ヴィンテージの特徴
  - ④飲み方：適温、グラスの形状や抜栓後の変化、相性の良い料理
- **ウイスキー**：
  - ②味わい：ピート（スモーキーさ）の有無と強さ、樽由来の香味（シェリー樽・バーボン樽等）、甘みと余韻
  - ③背景：蒸留所の地域（スコッチ地域区分・ジャパニーズ等）・歴史、原酒構成・製法の特徴
  - ④飲み方：ストレート／トワイスアップ／ロック／ハイボール等の向き不向き
- **ジン**：
  - ②味わい：ジュニパーベリーを基調とした主なボタニカルの香りの立ち方（柑橘・スパイス・ハーブ・フローラル等）、ドライさ
  - ③背景：蒸留所の国・地域、ベーススピリッツや特徴的なボタニカル・蒸留法
  - ④飲み方：ジントニック／ジンソーダ／マティーニ等のカクテル適性、添えるガーニッシュ
- **焼酎**：
  - ②味わい：原料（芋・麦・米・黒糖等）由来の香りと甘み、麹（黒麹・白麹・黄麹）や蒸留法（常圧・減圧）によるコクとキレ
  - ③背景：蔵元の所在地、原料品種や仕込み・熟成（甕貯蔵・樽熟成等）の特徴
  - ④飲み方：ロック／水割り／お湯割り／ソーダ割り等の適した割り方
- **ビール**：
  - ②味わい：ホップの香りと苦味（IBU感）、モルトのコク・甘み・ロースト感、酸味やマウスフィール
  - ③背景：ブルワリー（醸造所）の所在地・成り立ち、そのビアスタイルの特徴や副原料
  - ④飲み方：適温、注ぎ方やグラス、相性の良い食事
- **ブランデー**：
  - ②味わい：果実香・熟成香（バニラ・ナッツ・ドライフルーツ・スパイス等）、まろやかさと余韻
  - ③背景：産地（コニャックのクリュ、アルマニャック、カルヴァドス等）、メゾンと熟成年数・等級の背景
  - ④飲み方：ストレート（チューリップグラス等）、加水、食後酒としての楽しみ方
- **シェリー**：
  - ②味わい：タイプ（フィノ／マンサニージャ／オロロソ等）そのものが決める辛口・甘口、フロールや酸化熟成の風味
  - ③背景：ボデガ（生産者）と熟成地、ソレラ・システムによる熟成の特徴
  - ④飲み方：適温（フィノ等はしっかり冷やす等）、タパス等の合わせ方
- **ウォッカ**：
  - ②味わい：原料由来の口当たり（なめらかさ・とろみ・キレ）とほのかな甘み
  - ③背景：生産国・蒸留所、蒸留回数や濾過方法・仕込み水の特徴
  - ④飲み方：冷凍庫で冷やしてストレート、ソーダ・トニック割り、カクテルベース
- **その他**：
  - ②味わい：主原料・製法に由来する香り、甘み・酸味・苦味・アルコール感のバランス
  - ③背景：生産者・産地、そのお酒の分類（リキュール・ラム・テキーラ等）と製法
  - ④飲み方：ストレート／ロック／ソーダ割り等の定番の飲み方

### (3) 相場目安（referencePrice）の推定条件
- 通貨は日本円（税込目安の整数）のみ。
- 容量（volumeMl）が異なる商品の価格は絶対に混ぜない（720ml の瓶に 1800ml の価格を入れない）。
- 同じ商品・同じ容量と確認できない場合は空欄（null）。
- fetchedDate は相談実行日（YYYY-MM-DD）。購入価格とは構造上完全分離する。

### (4) 取り込み JSON スキーマと検証ルール
- **GeminiImportPayload**：
  - `name`: string（必須・非空）
  - `category`: SakeCategory（必須・固定10種）
  - `abv`: number | null
  - `volumeMl`: number | null
  - `categoryAttributes`: Record<string, string | number | null>
  - `description`: { summary: string; tasteProfile: string; background: string; servingSuggestion: string } | null
  - `sources`: Array<{ title?: string; url: string }>
  - `referencePrice`: { estimatedPriceYen: number | null; fetchedDate?: string | null; note?: string } | null
- **2段階検証**：
  - **エラー（弾く）**：壊れた JSON 構文、name の欠落・空欄、固定10種以外の未知カテゴリ、不正な数値型。既存フォームを保護し日本語エラーを表示。
  - **警告（通す）**：未知の属性キーの除外、不正な出典 URL の除外、相場目安取得日の当日補完、解説の一部の欠落。自動正規化して取り込み、警告バナーを表示。

## 3. 写真処理と保存の仕組みの確定

### (1) 写真処理パイプライン
1. **リサイズ**：長辺最大 1600px（アスペクト比維持、拡大はしない）。
2. **圧縮と EXIF 除去**：Canvas に描画し、JPEG（品質 0.82）へ再エンコードすることで位置情報等の EXIF を完全除去。
3. **ハッシュとサイズ**：Base64 から SHA-256 hex（64桁）および byteSize を算出。
4. **上限**：1本につき最大 10枚。

### (2) 代表写真の指定・追加・差し替え・削除
- 代表写真（primaryPhotoId）は明示指定可能。未指定時は photoIds[0]。代表写真が削除された場合は残る先頭が自動昇格。写真が0枚の場合は primaryPhotoId = null。
- 差し替え時は新しい PhotoRecord を生成して配列内の位置を引き継ぎ、古いレコードはクリーンアップ。

### (3) 保存の仕組みと Drive 連携への境界
- リサイズ・圧縮済みの写真は IndexedDB の photos ストアに PhotoRecord として保持。localStorage には保存しない。
- PhotoRecord.bottleId は必ず親 BottleRecord.id と紐づく（バックアップ整合性 photo.bottleId === bottle.id を維持）。
- 複数本一括登録や流用登録時は、各ボトルごとに独立した PhotoRecord（新しい UUID）を生成して保存。
- ステップ2〜3（Drive同期前）において、ボトルの photoIds から外れた未同期写真は photos ストアから物理削除して容量圧迫とバックアップ不整合を防ぐ。ボトル自体の論理削除時は紐づく写真も論理削除（deleted = true）する。

## 4. 再取り込み時の上書き防止（userEditedFields）と重複警告・流用・一括登録

### (1) userEditedFields の運用
- ユーザーが手動編集した項目名（name, category, abv, volumeMl, categoryAttributes.*, description.*, sources, referencePrice）を userEditedFields 配列に記録。
- 再取り込み時、userEditedFields に含まれる項目は Gemini JSON の値で上書きせず維持する。含まれない項目のみ更新する。

### (2) 重複警告
- 既存の未削除ボトルに同一銘柄キー（または正規化名＋種類）が存在する場合に警告バナーを表示。
- 在庫・飲んだ記録・手放した酒の内訳を示し、流用への切り替えや別個体としての追加を促す。

### (3) 既存銘柄からの流用
- 過去のボトルから属性・解説・相場目安・写真（任意）を引き継ぐ。状態は unopened、購入情報は空欄にリセット。

### (4) 複数本一括登録
- 新規登録時に本数 N（1〜10）を指定し、互いに異なる UUID を持つ N 本の BottleRecord と写真を単一トランザクションで一括生成・保存。

## 6. 受入条件

1. **複数枚写真・リサイズ・EXIF 除去・代表指定**：複数枚写真（表・裏・箱等）を登録でき、一覧には代表写真が表示され、詳細で全枚閲覧できること。写真の追加・差し替え・削除・代表変更ができ、不要写真が残らずバックアップ整合性を保つこと。
2. **Gemini 相談と背景写り込み注意**：登録画面で背景写り込みへの注意が明示され、プロンプトをワンタップでコピーできること。
3. **JSON 取り込み検証**：結果 JSON を貼り付けて取り込め、保存前に確認・手修正できること。壊れた JSON や未知の種類はエラー表示で弾かれること。
4. **4部構成解説・出典・相場目安**：解説が4部構成で保持・表示され、出典 URL を確認できること。相場目安が購入価格と混ざらず別枠で保持されること。
5. **手編集項目の保護**：手編集した項目が JSON 再取り込みで上書きされないこと。
6. **重複警告・流用・一括登録**：同一銘柄の重複が警告されること。既存銘柄から流用して登録できること。複数本（1〜10本）をまとめて登録でき、一覧でまとまって表示されること。
7. **初期状態と編集・削除**：登録時の状態の既定が未開封で、開封済み（開封日空欄可）も登録できること。登録後の編集・削除ができること。標準検証コマンド npm run verify が exit 0 であること。
